   Material 1 `compress` function:
   ```python
   def compress(messages, keep=KEEP_RECENT):
       """先頭のsystemと直近keep件を残し、間を1件の要約に畳む。

       要約もモデルに書かせる。つまり**畳んだ時点で情報は失われる**。
       何を残すかを指示で決めるのが設計で、「全部残して」は不可能な相談になる。
       """
       head = [m for m in messages if m["role"] == "system"][:1]
       body = [m for m in messages if m["role"] != "system"]
       if len(body) <= keep:
           return messages
       old, recent = body[:-keep], body[-keep:]
       transcript = "\n".join(f"{m['role']}: {m['content']}" for m in old)
       summary = ask([
           {"role": "system", "content":
            "会話の要約係です。後で参照する事実（固有名詞・数値・決めごと）を"
            "落とさずに、5行以内の箇条書きにしてください。"},
           {"role": "user", "content": transcript},
       ])["content"]
       note = {"role": "system", "content": f"【これまでの会話の要約】\n{summary}"
       return head + [note] + recent
   ```

   Material 1 `remember` and `recall`:
   ```python
   def remember(text):
       """覚えておきたい一行を追記する。第4回の write_file の親戚。"""
       with MEMORY_PATH.open("a", encoding="utf-8") as f:
           f.write(f"- {text}\n")
       return f"覚えました: {text}"

   def recall(keyword=""):
       """記憶を読み出す。keyword があれば含む行だけ返す。

       これは検索と呼ぶには素朴すぎる（文字が一致しないと引けない）。
       その限界が第8回の入口になる。
       """
       if not MEMORY_PATH.exists():
           return "（まだ何も覚えていません）"
       lines = MEMORY_PATH.read_text(encoding="utf-8").splitlines()
       hit = [ln for ln in lines if keyword in ln] if keyword else lines
       return "\n".join(hit) if hit else f"（「{keyword}」を含む記憶はありません）"
   ```

   圧縮機構がなければ、会話は無限に続き、モデルの文脈が上限に達して正確な回答ができなくなります。この機構がないと、履歴が膨張し、毎回多くのトークンを消費することになります。

   ```python
   def compress(messages, keep=KEEP_RECENT):
       """先頭のsystemと直近keep件を残し、間を1件の要約に畳む。

       要約もモデルに書かせる。つまり**畳んだ時点で情報は失われる**。
       何を残すかを指示で決めるのが設計で、「全部残して」は不可能な相談になる。
       """
       head = [m for m in messages if m["role"] == "system"][:1]
       body = [m for m in messages if m["role"] != "system"]
       if len(body) <= keep:
           return messages
       old, recent = body[:-keep], body[-keep:]
       transcript = "\n".join(f"{m['role']}: {m['content']}" for m in old)
       summary = ask([
           {"role": "system", "content":
            "会話の要約係です。後で参照する事実（固有名詞・数値・決めごと）を"
            "落とさずに、5行以内の箇条書きにしてください。"},
           {"role": "user", "content": transcript},
       ])["content"]
       note = {"role": "system", "content": f"【これまでの会話の要約】\n{summary}"
       return head + [note] + recent
   ```

   ```python
   def remember(text):
       """覚えておきたい一行を追記する。第4回の write_file の親戚。"""
       with MEMORY_PATH.open("a", encoding="utf-8") as f:
           f.write(f"- {text}\n")
       return f"覚えました: {text}"

   def recall(keyword=""):
       """記憶を読み出す。keyword があれば含む行だけ返す。

       これは検索と呼ぶには素朴すぎる（文字が一致しないと引けない）。
       その限界が第8回の入口になる。
       """
       if not MEMORY_PATH.exists():
           return "（まだ何も覚えていません）"
       lines = MEMORY_PATH.read_text(encoding="utf-8").splitlines()
       hit = [ln for ln in lines if keyword in ln] if keyword else lines
       return "\n".join(hit) if hit else f"（「{keyword}」を含む記憶はありません）"
   ```

会話が長くなるとモデルの文脈が上限に達し、情報が飛ばされたり正確な回答ができなくなったりします。この状態が続くと、ユーザーの意図が伝わらず、会話の価値が低下します。

## 圧縮：古い会話を要約に畳む
圧縮機構がなければ、会話は無限に続き、モデルの文脈が上限に達して正確な回答ができなくなります。この機構がないと、履歴が膨張し、毎回多くのトークンを消費することになります。

```python
def compress(messages, keep=KEEP_RECENT):
    """先頭のsystemと直近keep件を残し、間を1件の要約に畳む。

    要約もモデルに書かせる。つまり**畳んだ時点で情報は失われる**。
    何を残すかを指示で決めるのが設計で、「全部残して」は不可能な相談になる。
    """
    head = [m for m in messages if m["role"] == "system"][:1]
    body = [m for m in messages if m["role"] != "system"]
    if len(body) <= keep:
        return messages
    old, recent = body[:-keep], body[-keep:]
    transcript = "\n".join(f"{m['role']}: {m['content']}" for m in old)
    summary = ask([
        {"role": "system", "content":
         "会話の要約係です。後で参照する事実（固有名詞・数値・決めごと）を"
         "落とさずに、5行以内の箇条書きにしてください。"},
        {"role": "user", "content": transcript},
    ])["content"]
    note = {"role": "system", "content": f"【これまでの会話の要約】\n{summary}"
    return head + [note] + recent
```

この関数は、古いメッセージを要約して会話のリストを整理します。

## 長期記憶：ファイルに残す
ファイルに覚めておく仕組みがなければ、一度学んだ事実を二度と呼び出せなくなります。重要な情報が失われると、モデルは毎回ゼロから学習することになり、効率が悪くなります。

```python
def remember(text):
    """覚えておきたい一行を追記する。第4回の write_file の親戚。"""
    with MEMORY_PATH.open("a", encoding="utf-8") as f:
        f.write(f"- {text}\n")
    return f"覚えました: {text}"

def recall(keyword=""):
    """記憶を読み出す。keyword があれば含む行だけ返す。

    これは検索と呼ぶには素朴すぎる（文字が一致しないと引けない）。
    その限界が第8回の入口になる。
    """
    if not MEMORY_PATH.exists():
        return "（まだ何も覚えていません）"
    lines = MEMORY_PATH.read_text(encoding="utf-8").splitlines()
    hit = [ln for ln in lines if keyword in ln] if keyword else lines
    return "\n".join(hit) if hit else f"（「{keyword}」を含む記憶はありません）"
```

この関数は、メモリファイルに一行追記したり、条件に合う行を探して返したりします。

### 解答例
解答例を提示します。記憶の仕組みがなければ、答えに一貫性がなくなります。

1. 圧縮時に情報が失われる理由は、古い会話を要約する際、モデルがすべての詳細を記憶できるわけではなく、重要な事実（固有名詞・数値・決めごと）のみを5行以内の箇条書きにするため、些細な表現や文脈の一部が省かれるからです。
2. ファイルに覚めておくことの利点は、一度学んだ事実（氏名・居住地・出来事など）を二度と呼び出せるようになり、モデルが毎回ゼロから状態を再構築する必要がなくなるため、会話の効率が向上するからです。
3. 圧縮関数 `compress` では、先頭の system 直近 `keep` 件のメッセージを残し、それ以前の古いメッセージを1件の要約に畳みます。要約に含めてよい情報の基準は「後で参照する事実（固有名詞・数値・決めごと）を落とさずに5行以内の箇条書きにする」ことです。例えば `summary = ask([{"role": "system", "content": "会話の要約係です。後で参照する事実を5行以内の箇条書きにしてください。"}])["content"]` のようにモデルに要約させるコードを1行書くことができます。
4. `remember` 関数は `with MEMORY_PATH.open("a", encoding="utf-8") as f: f.write(f"- {text}\n")` としてファイルの最後に一行を追記します。重要な部分は `'a'` モードで追記することと、 `encoding="utf-8"` で文字化
