## 前回の復習
前回の recall は一致しないと引けないという仕組みが無いと、記憶が増えても必要な情報が見つかります。意味で探さないと、関連する記憶が文字通りの一致だけで埋もれてしまいます。第1回のwhileループから第4回のファイル作業までを経て、道具の貸し出しと選択を学んできました。今回は記憶の中から意味の近いものを探る仕組みを作ります。
## 全部は入らない、だから探す
この仕組みが無いと、記憶が増えると、何に関連するか一覧できなくなります。文字が一致しないと引けない前回の仕組みでは、似た意味の記憶とそうでないものを区別できません。記憶のリストが長くなると、目的の情報を探し出すのに時間がかかり、重要な記憶が見逃されます。
## 埋め込みという物差し
この仕組みが無いと、意味の近さが数で測れないと、似た意味の記憶とそうでないものを仕分けられません。エンバー関数は文章を数のリストに変え、コサイン関数は2つのリストの向きのなじみ具合を0から1までの数で返します。この2関数を使えば、文字の違いを無視して意味の近さが分かります。  
def embed(text):
    """文を数のベクトルに変える。近い意味の文は近い方向を向く。"""
    return post("/api/embeddings", {"model": EMBED_MODEL, "prompt": text})["embedding"]
def cosine(a, b):
    """2つの向きがどれだけ揃っているか。1に近いほど同じ方向を向いている。
    長さを割り落として向きだけを見るので、文の長短に振り回されない。
    """
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb) if na and nb else 0.0
この2関数は、文章を数のリストに変え、2つのリストの向きのなじみ具合を0から1までの数で返します。意味が近いほど値が1に近く、文字が違っても方向が似ていれば高いスコアになります。

## 100行の素朴な検索
この仕組みが無いと、問いに近い記憶を列挙する手立てが無く、ただの文字一致しかできません。search関数は埋め込みベクトルを比べて、問いと近い順に上位k件をリストアップします。検索結果はスコア付きで返され、スコアが高いほど意味が近いことを示します。  
def search(query, k=2):
    """問いに近い順に k 件返す。総当たりで全件と比べるだけ。"""
    qv = embed(query)
    scored = [(cosine(qv, v), text) for text, v in INDEX]
    scored.sort(reverse=True)
    return scored[:k]
この関数は、問いのベクトルと記憶のベクトルを比べて、近い順に上位k件をリストアップします。スコアは0に近いほど離れており、1に近いほど意味が似ています。

## 練習問題
1. 意味で探す記憶において、埋め込みベクトルの次元数が変わると検索精度にどのような影響がありますか。理由を説明してください。
2. 検索関数が無いと、LLMエージェントは自分の記憶をどのように活用できなくなりますか。理由を説明してください。
3. 余弦類似度のスコアが0.5未満のとき、どのようなことが起きますか。
4. build_index関数でインデックスを再構築する際、注意すべき点は何ですか。
5. ユーザーの問いに対する recall ツールの結果を受けて、次の応答をどう生成しますか。

### 解答例
1. 次元数が増えるとベクトルの表現力が高まり、意味の微細な違いも捉えやすくなりますが、次元が高すぎると計算量が増え、逆に低いと情報が足りなく精度が下がります。理由は、次元が低いと方向の表現が粗くなり、似た意味でも低スコアになりやすいからです。
2. 検索関数が無いと、エージェントは問いの意味に基づいて関連のある記憶を探せず、文字が一致する場合しか記憶にアクセスできません。理由は、意味の近さを数で比べる手立てが無く、関連の深い記憶が見逃されるからです。
3. 余弦類似度のスコアが0.5未満のとき、2つの文の向きがかなり異なり、意味があまり似ていないことを示します。実験ログでは0.308のような低スコアは、記憶にない話題や関連の薄い内容に対して返され、実用的な答えとはなりにくいです。
4. build_index関数でインデックスを再構築する際、メモリに載っている記憶のリストが変わるとそれに合わせてベクトルの計算し直しが必要です。注意点は、新しい記憶を追加または削除したたびにインデックスを更新しないと、古いデータで検索が行われることです。理由は、インデックスが古ければ検索結果の精度が低下するからです。
5. ユーザーの問いに対する recall ツールの結果を受けて、次の応答はツールの結果に出た記憶を踏まえて生成されます。理由は、ツールで探した情報がなければ、エージェントは自分の知識のみで答えることになり、的外れの回答になりやすいからです。
